## 三、完整配音稿

### 0:00～0:25　开场

**画面/操作：** 片头依次显示论文题目、“LabGuard 2.0”和系统首页。可在右下角保留学校、学院、姓名、学号信息。

**配音稿：**

各位老师好，我是软件学院软件工程专业的学生许孟禹。我的毕业设计题目是《基于 Spring Boot 的高校实验室安全准入与预约管理系统》。下面我将结合论文的设计思路，演示系统的核心业务流程。

### 0:25～1:15　研究背景与问题

**画面/操作：** 展示三组关键词：“培训记录分散”“资格核验滞后”“预约冲突与追溯困难”，随后切到论文中的系统用例图或功能结构图。

**配音稿：**

随着实验教学、科研训练和创新活动不断增加，高校实验室的开放频次、人员流动和设备使用强度都在上升。传统依靠纸质登记、电子表格和线下通知的方式，容易出现培训记录分散、准入资格核验不及时、预约时段冲突、设备状态不清以及安全责任难以追溯等问题。

因此，本课题不只是增加一个信息录入页面，而是希望把“培训、考试、资格审核、实验室预约、使用与安全记录”串成一条可验证、可查询、可追溯的业务链。系统面向学生、教师和管理员三类角色，分别承担学习申请、业务审核和平台管理职责。

### 1:15～2:00　系统定位与总体架构

**画面/操作：** 展示登录页、登录后的“安全准入总览”；短暂切换到系统分层架构图和数据库表清单。

**配音稿：**

系统采用浏览器和服务器模式。后端基于 Java 21 和 Spring Boot 3.5.15，使用 Spring Boot Web 提供 REST 接口，由 Spring JDBC 负责数据访问，MySQL 保存业务数据；前端使用 Vue 3 和 Vite 构建响应式单页界面。

整体按照表示层、控制层、业务服务层、数据访问层和数据存储层进行划分。系统共包含用户管理、安全培训、准入考试、实验室、预约、设备、安全和系统管理等八个一级模块，数据库设计了十五张业务表。这种分层方式让页面交互、业务规则和数据访问各有边界，也为后续扩展认证、通知和统计能力保留了空间。

### 2:00～3:05　安全培训演示

**画面/操作：** 使用学生账号登录，进入“培训课程”。点击一门课程，切换两个章节，展示学习进度；最后停留在“学习记录”或已完成状态。

**配音稿：**

进入系统后，首页集中展示准入人数、待审核预约、设备数量和危险源数量。学生可以在“培训课程”中查看已发布课程，系统按章节呈现学习目标、操作规范和应急处置要求。

每完成一个章节，进度会保存到学习记录；到达最后一章后，还需要勾选“已阅读并理解安全要求”才能确认完成。系统会校验课程是否发布、进度是否合法以及记录是否已经完成，避免通过重复提交随意改变学习状态。这样，安全培训就不只是一份静态材料，而是能够支撑后续考试和资格审核的业务依据。

### 3:05～4:45　在线考试与准入审核

**画面/操作：** 进入“在线考试”，快速展示题目数量和答题状态；展示提交后的成绩弹窗和考试记录。随后切换教师账号，进入“准入资格”，点击“通过”，选择适用实验室和未来有效期，提交审核。

**配音稿：**

完成培训后进入在线考试。系统从题库中随机抽取十道题组成试卷，并把本次题号保存在当前会话中。页面只下发题目和选项，不下发标准答案；提交时，后端按照会话中的固定题号重新读取标准答案，完成判分并折算为百分制，达到六十分即通过。

这里需要强调，考试通过并不等于自动获得实验室准入资格。教师或管理员还要进入“准入资格”页面，结合已完成课程、最近一次考试成绩、适用实验室和有效期进行人工审核。只有培训、考试和人工审核同时满足，学生才能在对应实验室内发起预约。该设计把安全教育结果与管理责任共同落到了具体人员和具体实验室上。

### 4:45～6:20　预约闭环与并发控制

**画面/操作：** 回到学生账号，进入“预约管理”，选择开放实验室、未来日期和标准时段，填写用途并提交。再提交一次相同实验室、日期和时段的申请，展示冲突提示。随后切换到教师账号，对第一条待审核预约执行“通过”，展示审核人和状态。

**配音稿：**

实验室预约是系统的核心业务。学生提交预约时，只能选择处于开放状态的实验室，日期必须在允许范围内，时段使用统一的三档时间，并填写实验目的。

后端会在同一个事务中依次校验：实验室是否开放、日期和时段是否合法、用户是否拥有该实验室当前有效的准入资格，以及该用户和该实验室是否已经存在冲突预约。校验通过后，预约以“待审核”状态保存。这里还使用了行锁，先锁定用户，再锁定实验室，避免两个并发请求同时通过检查后重复占用同一时段。

如果再次提交同一实验室、同一日期和时段，系统会提示“该时段已被预约”；如果用户没有对应实验室的有效资格，则会在进入审核队列之前被直接拦截。预约通过后，记录中会保留审核人，后续可以追责。由此形成“资格决定能否申请、冲突检测决定能否占用、人工审核决定是否放行”的三级控制。

### 6:20～7:35　设备与安全管理演示

**画面/操作：** 使用教师账号依次展示“设备台账”“使用登记”“危险源”“违规记录”“安全检查”。在安全检查中展示问题描述、整改结果和实验室状态。

**配音稿：**

除人员和场地外，系统还覆盖实验室运行过程中的设备和安全风险。设备台账保存设备编号、所属实验室、型号和运行状态；使用登记记录使用人、时间、用途和归还情况。维修中或停用的设备不能直接登记使用，登记状态还会联动设备台账。

安全管理部分包括危险源、违规记录和安全检查。危险源记录防护要求和应急措施；违规记录保存责任人、处理结果和闭环状态；安全检查记录问题与整改结果。当检查结果为“停用整改”时，系统会同步调整实验室状态，待整改完成后再恢复开放，使检查、处置和资源状态形成联动。

### 7:35～8:35　统计、公告与操作日志

**画面/操作：** 切换管理员账号，回到“安全准入总览”，依次指向指标卡、实验室运行状态、预约热度和安全公告；随后打开“通知公告”和“操作日志”。

**配音稿：**

管理员可以通过工作台查看当前有效准入人数、待审核预约、设备数量、危险源数量、实验室运行状态和预约热度，快速掌握实验室整体情况。

通知公告用于发布培训安排、开放调整和设备维护信息；操作日志记录登录、数据维护、资格审核和预约审核等关键行为，包含操作人、模块、时间和详情。角色权限由后端会话和拦截器共同校验，密码使用 BCrypt 保存，写操作同时进行 CSRF 校验。这样，系统不仅展示业务结果，也保留了过程证据。

### 8:35～9:20　测试、总结与展望

**画面/操作：** 展示论文中的功能测试结果表或测试统计；最后切到系统首页，并在画面上列出“闭环准入、事务冲突控制、全过程留痕”三个关键词。

**配音稿：**

论文中的测试围绕有效登录、错误密码、重复注册、课程完成、自动判分、资格审核、合格预约、时间冲突和无资格预约等场景展开，并补充了浏览器兼容性、易用性和页面响应检查。测试结果显示，页面反馈与数据库状态一致，核心业务链路能够正确执行。项目现有自动化测试报告也显示，服务与安全相关测试均通过。

本系统的主要特点可以归纳为三点：第一，以培训和考试结果支撑人工准入审核；第二，以事务和冲突检测保证预约数据一致性；第三，以日志和设备、安全检查记录支持全过程追溯。

当前系统更适合校内中小规模应用。后续可以继续接入学校统一身份认证，增加预约到期自动释放、消息提醒、移动端适配、自动化压力测试和更完整的统计报表。我的演示到此结束，谢谢各位老师。

## 四、不同时长版本的处理方式

- 开场与背景：45 秒
- 系统定位与架构：45 秒
- 培训、考试、资格：1 分 40 秒
- 预约闭环：1 分 30 秒
- 管理能力与测试：1 分钟

### 11～12 分钟完整版

在标准版基础上增加四段：

1. 用 `20260102 / 1234` 演示无资格学生提交预约时的拦截提示。
2. 打开 `ReservationService` 与 `ReservationRepository`，展示事务、行锁、资格有效期和冲突查询的关键代码。
3. 现场新增一条设备使用登记，展示设备状态联动；新增一条“停用整改”安全检查，展示实验室状态变化。
4. 展示测试报告和数据库表结构，说明现有测试覆盖及当前原型在统一认证、提醒、自动释放和大规模压力测试方面的不足。

## 五、录制与答辩提醒

- 口播时把“功能演示”和“论文结论”交替推进，不要长时间连续点页面。
