# LabGuard 项目运行环境与部署说明

本文档说明 LabGuard 高校实验室安全准入与预约管理系统的运行环境、环境搭建步骤、默认账号和常见注意事项。项目采用 Spring Boot 3 + Vue 3 架构，默认通过 `8080` 端口提供前后端一体化访问。

## 一、项目运行环境

### 1.1 基础环境

| 组件 | 要求 | 用途 |
| --- | --- | --- |
| 操作系统 | Windows 10/11 x64 | 项目自带启动脚本均为 `.bat` 文件 |
| JDK | JDK 21 | 编译和运行 Spring Boot 后端 |
| MySQL | MySQL 5.7.44 | 保存用户、实验室、预约、考试等业务数据 |
| Node.js | 20.x 中不低于 20.19.0，或不低于 22.12.0 的更高版本 | 编译 Vue 3 前端 |
| npm | 随 Node.js 安装，建议 10 及以上 | 安装前端依赖 |
| Maven | 无需单独安装 | 使用项目自带的 `mvnw.cmd` 和 Maven 3.9.16 |
| 浏览器 | Chrome、Edge 等现代浏览器 | 访问系统页面 |

版本约束说明：

- 项目 `pom.xml` 指定 `java.version=21`，使用 JDK 8、JDK 11 或 JDK 17 均不能正常编译。
- 前端使用 Vite 7，Node.js 必须满足 `^20.19.0 || >=22.12.0`。
- 项目声明的数据库基线为 MySQL 5.7.44。若改用其他 MySQL 版本，应先在目标机器完成兼容性验证。
- 首次构建需要联网下载 Maven 和 npm 依赖。

### 1.2 端口与网络

| 项目 | 默认值 | 说明 |
| --- | --- | --- |
| 系统访问地址 | `http://localhost:8080/` | 打包后前后端统一地址 |
| 后端端口 | `8080` | 可通过 `SERVER_PORT` 修改 |
| 前端开发端口 | `5173` | 仅开发模式使用 |
| MySQL 地址 | `localhost:3306` | 数据库名默认为 `lab_safety` |

前端开发服务器会把 `/api` 请求代理到 `http://localhost:8080`，因此开发模式下建议保持后端端口为 `8080`。

### 1.3 构建与运行区别

- 仅运行已打包版本时，只需要 JDK 21、MySQL 和 `target/lab-safety-2.0.0.jar`。
- 从源码构建时，还需要 Node.js、npm 和网络；Maven 由项目内的 `mvnw.cmd` 自动准备。
- 数据库表和演示数据会在后端首次启动时自动初始化。一般情况下无需手动导入 SQL。

### 2.3 数据库默认连接信息

| 配置项 | 启动脚本中的值 | `application.yml` 未设置环境变量时的值 |
| --- | --- | --- |
| 数据库 | `lab_safety` | `lab_safety` |
| 用户名 | `root` | `root` |
| 密码 | `123456` | `1234` |
| 地址 | `localhost:3306` | `localhost:3306` |

两个 `.bat` 启动脚本会把数据库密码设置为 `123456`；直接执行 `java -jar` 且不设置环境变量时，会使用 `application.yml` 中的 `1234`。这是项目当前的配置差异，部署时必须统一，否则会出现 `Access denied for user 'root'`。

推荐做法是将本地 MySQL 的 `root` 密码设为 `123456`，与两个启动脚本保持一致。如果必须使用其他密码，应修改启动脚本中的 `DB_PASSWORD`，或在手动启动前显式设置环境变量。

## 三、搭建环境操作步骤

以下步骤以 Windows PowerShell 和项目目录 `D:\bishe\LabGuard-2.0.0` 为例。

### 3.1 安装并检查 JDK 21

1. 安装 JDK 21，可选择 Eclipse Temurin、Oracle JDK 或 Microsoft Build of OpenJDK。
2. 新建系统环境变量 `JAVA_HOME`，将其指向 JDK 21 安装目录。
3. 将 `%JAVA_HOME%\bin` 放到 `Path` 环境变量前列，避免旧版 Java 优先生效。
4. 重新打开 PowerShell，执行：

```powershell
java -version
javac -version
```

输出中应包含 `version "21"`。如果仍然显示 Java 8 或其他版本，说明 `Path` 中仍有旧版 Java，需要调整环境变量顺序后重新打开终端。

### 3.2 安装并启动 MySQL

1. 安装 MySQL 5.7.44，并选择安装 MySQL Server 和 MySQL 命令行工具或图形客户端。
2. 将 MySQL 服务设置为自动启动，服务名通常为 `MySQL57`，实际名称以本机服务列表为准。
3. 将 `root` 密码设置为 `123456`，与项目启动脚本保持一致。
4. 确认服务已启动：

```powershell
Get-Service | Where-Object { $_.Name -like "*mysql*" -or $_.DisplayName -like "*mysql*" }
```

状态应为 `Running`。如果 MySQL 客户端已加入 `Path`，可进一步执行：

```powershell
mysql --version
```

项目默认连接参数包含 `createDatabaseIfNotExist=true`，因此首次启动时会自动创建 `lab_safety` 数据库。所使用的数据库账号需要具备建库和建表权限。如果账号没有建库权限，可以先在 MySQL 中手动执行：

```sql
CREATE DATABASE IF NOT EXISTS lab_safety
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;
```

### 3.3 安装 Node.js 和 npm

1. 安装 Node.js 20.19 及以上版本，或 Node.js 22.12 及以上版本。
2. 重新打开 PowerShell 后执行：

```powershell
node --version
npm --version
```

Node.js 版本必须满足 Vite 7 的要求。Node.js 26 等较新版本虽然通常可以构建，但正式部署建议使用 Node.js 20 LTS 或 22 LTS 进行验证。

### 3.4 检查 Maven Wrapper

项目已包含 Maven Wrapper，无需全局安装 Maven。在项目根目录执行：

```powershell
.\mvnw.cmd -version
```

首次执行会下载 Maven 3.9.16 及相关依赖，需要能够访问 Maven 仓库。

### 3.5 获取并构建项目

进入项目根目录：

```powershell
cd D:\bishe\LabGuard-2.0.0
```

安装前端依赖：

```powershell
cd .\frontend
npm ci
```

`package-lock.json` 已存在，推荐使用 `npm ci` 获得与锁文件一致的依赖版本。如果没有锁文件，再使用 `npm install`。

构建前端：

```powershell
npm run build
```

构建结果会输出到 `src/main/resources/static`。不要直接修改该目录中的压缩文件，前端改动完成后应重新执行构建。

返回项目根目录并打包后端：

```powershell
cd ..
.\mvnw.cmd clean package
```

打包成功后生成：

```text
target\lab-safety-2.0.0.jar
```

### 3.6 启动系统

#### 方式一：运行已打包版本

确认 MySQL 已启动，然后双击：

```text
运行已打包项目.bat
```

该脚本会检查 `target\lab-safety-2.0.0.jar`，设置数据库连接参数并启动应用。浏览器访问：

```text
http://localhost:8080/
```

也可以在 PowerShell 中手动启动。建议显式设置数据库密码，避免使用配置文件中的旧默认值：

```powershell
$env:DB_USER = "root"
$env:DB_PASSWORD = "123456"
$env:DB_URL = "jdbc:mysql://localhost:3306/lab_safety?createDatabaseIfNotExist=true&useUnicode=true&characterEncoding=UTF-8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&useSSL=false"
java -jar .\target\lab-safety-2.0.0.jar
```

看到 Spring Boot 启动完成日志后，打开 `http://localhost:8080/`。

#### 方式二：使用一键开发启动脚本

完成一次 `npm ci` 后，可以双击：

```text
启动项目.bat
```

或执行：

```powershell
.\start-project.bat
```

该脚本会重新构建前端和后端，然后启动应用。脚本不会自动执行 `npm ci`，因此首次搭建必须先完成前端依赖安装。

#### 方式三：前后端分离开发

终端一启动后端：

```powershell
cd D:\bishe\LabGuard-2.0.0
$env:DB_USER = "root"
$env:DB_PASSWORD = "123456"
.\mvnw.cmd spring-boot:run
```

终端二启动前端开发服务器：

```powershell
cd D:\bishe\LabGuard-2.0.0\frontend
npm run dev
```

浏览器访问：

```text
http://localhost:5173/
```

开发页面中的 `/api` 请求会由 Vite 代理到 `http://localhost:8080`。

## 四、配置项说明

数据库和端口可以通过环境变量覆盖：

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `DB_URL` | `jdbc:mysql://localhost:3306/lab_safety?...` | JDBC 连接地址 |
| `DB_USER` | `root` | 数据库用户名 |
| `DB_PASSWORD` | 配置文件为 `1234`，启动脚本覆盖为 `123456` | 数据库密码 |
| `SERVER_PORT` | `8080` | 后端 HTTP 端口 |

`src/main/resources/application.yml` 中的其他运行参数：

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `labguard.security.session-timeout-minutes` | `30` | 登录会话有效时间，单位分钟 |
| `labguard.security.max-login-attempts` | `5` | 连续登录失败次数上限 |
| `labguard.security.login-block-minutes` | `10` | 触发限制后的锁定时长，单位分钟 |
| `labguard.reservation.max-advance-days` | `60` | 最多可提前预约的天数 |
| `labguard.exam.question-count` | `10` | 每次考试抽取的题目数量 |

如果题库数量少于 `question-count`，系统会使用全部可用题目。

## 五、注意事项

### 5.1 环境与启动

- 必须使用 JDK 21。出现 `UnsupportedClassVersionError` 或 Java 版本相关编译错误时，首先检查 `java -version` 和 `JAVA_HOME`。
- 启动前必须确认 MySQL 服务处于运行状态。
- `8080` 端口不能被其他进程占用；被占用时应停止冲突进程，或修改 `SERVER_PORT`，同时调整前端开发代理。
- 两个 `.bat` 文件会覆盖当前进程中的 `DB_USER`、`DB_PASSWORD` 和 `DB_URL`。数据库账号不同时，需要同步修改脚本或在命令行手动启动。
- `运行已打包项目.bat` 不会重新编译项目。源码或前端资源变更后，需要重新执行前端构建和 Maven 打包。
- 首次启动需要下载依赖，生产网络受限时应提前准备 Maven 和 npm 离线依赖。

### 5.2 数据库与初始化

- 后端每次启动都会执行 `schema.sql` 和 `data.sql`。建表语句带 `if not exists`，演示数据带 `where not exists`，正常启动不会重复插入相同种子数据。
- `schema.sql` 只负责创建缺失的表，不负责迁移已有表结构。升级代码前应先备份数据库；旧数据库结构不兼容时，需要单独编写迁移脚本或重建开发库。
- 数据库名称必须与 `DB_URL` 中的名称一致，默认为 `lab_safety`。
- 演示数据中的预约日期为 2026 年 7 月，已经早于当前日期。演示新的预约流程时，应选择“今天之后且不超过 60 天”的日期和未占用时段。
- 根目录的 `lab_safe.sql` 是从 MySQL 8.0 导出的数据库快照，其中使用了 MySQL 8.0 的 `utf8mb4_0900_ai_ci` 排序规则，不适合直接导入 MySQL 5.7。常规部署应让应用自动执行 `schema.sql` 和 `data.sql`，不要用该快照替代初始化流程。
- 数据修改会持久化到 MySQL。更新或演示前应备份 `lab_safety` 数据库。

### 5.3 账号与安全

- `admin / 1234`、`student / 1234`、`teacher / 1234` 等仅用于开发和演示，不得直接用于公网或正式环境。
- 演示账号首次登录后会自动将密码升级为 BCrypt，但密码强度仍然只有 4 位。正式使用前应修改默认账号密码或删除演示账号。
- 新注册用户密码要求为 8 到 72 个字符，默认账号的 `1234` 属于兼容演示数据的弱密码。
- 系统使用会话登录，会话默认 30 分钟失效；连续 5 次登录失败会触发 10 分钟限制。
- 系统写操作包含 CSRF 校验。不要绕过前端直接调用受保护 API，否则需要同时携带会话和 CSRF 令牌。
- 生产环境应使用专用数据库账号，只授予 `lab_safety` 库所需权限，避免直接使用 MySQL `root`。
- 不建议将 `8080` 直接暴露到公网。正式部署应使用反向代理、HTTPS、防火墙和访问日志，并配置安全的主机名及端口。

### 5.4 前端构建

- 修改 `frontend` 下的源码后必须重新执行 `npm run build`，否则 `8080` 端口仍会展示旧的前端资源。
- `npm ci` 会根据 `package-lock.json` 安装依赖。升级 Vite、Vue 或插件后，应同步更新并提交锁文件。
- Node.js 版本过低会出现 Vite 引擎版本不兼容错误，应升级到 20.x 的 20.19.0 及以上，或不低于 22.12.0 的更高版本。
- 页面空白时，依次检查前端是否构建成功、`src/main/resources/static/index.html` 是否存在、后端是否重新打包，以及浏览器控制台中的接口错误。

## 六、常见故障排查

| 现象 | 常见原因 | 处理方式 |
| --- | --- | --- |
| 提示 Java 版本不支持 | 当前 `java` 仍指向 JDK 8 等旧版本 | 安装 JDK 21，调整 `JAVA_HOME` 和 `Path` 后重开终端 |
| `Access denied for user 'root'` | 脚本密码 `123456` 与 MySQL 实际密码不一致 | 统一 root 密码，或修改脚本和环境变量 |
| `Communications link failure` | MySQL 未启动、端口不是 3306 或连接被拒绝 | 启动 MySQL 服务并检查 `DB_URL` |
| 提示不能创建数据库 | MySQL 账号缺少建库权限 | 使用有权限的账号，或手动创建 `lab_safety` |
| 登录失败次数过多 | 连续输错 5 次触发限制 | 等待 10 分钟后重试，或检查是否使用了错误账号 |
| 8080 页面无法访问 | 端口被占用或后端未启动成功 | 查看启动日志，确认 `Started LabSafetyApplication` |
| 前端页面打不开或显示旧页面 | 未执行前端构建或后端未重新打包 | 执行 `npm run build` 和 `.\mvnw.cmd clean package` |
| 演示预约提交失败 | 日期已过、超过 60 天、实验室未开放或时段冲突 | 更换为未来 60 天内的开放时段 |
